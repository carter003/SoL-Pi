# sol-omp 快速开发实施计划

> 版本：计划 v1.0 · 2026-09-12  
> 定位：面向 AI 开发的轻量实施计划，以真实跑通为优先。  
> 状态：待实施；本文不是已经完成的兼容性、功能或性能测试报告。

## 1. 这次要交付什么

创建独立的 `sol-omp` 项目，将 NVIDIA SoL-Pi 的适用机制接入 oh-my-pi（OMP）。先在一个实际使用的 OMP 版本、一个开发环境中运行起来，再补充自动化维护和扩展能力。

**本次优先交付：ObservationPack + Action Fusion。** Evidence-Preserving Reducer 放到后续阶段；不实现 Online Context Compact。

开发顺序：

```text
真实加载扩展 → ObservationPack 跑通 → Action Fusion 跑通 → 最小测试、安装说明与交付
```

如果 Action Fusion 的宿主命令权限接口暂时无法接通，先交付可运行的 ObservationPack 预览版，同时给出具体阻塞证据。不能因此停下整个项目，也不能把未完成的 Action Fusion 标记为完成。

### 相比原方案，明确简化

| 内容 | 本次处理 |
|---|---|
| 与原生 OMP 的性能、成本、成功率对照 | 省略，不作为开发或交付前置条件 |
| 多模型、大规模任务集、统计分析 | 省略 |
| Linux、Windows、多个 OMP 版本的完整矩阵 | 后置，先验证当前实际开发环境和一个固定版本 |
| 通用 Runtime Contract、多层 Core/Adapter 框架 | 不建设，只做功能需要的少量适配 |
| 自动同步上游、定时最新版本兼容检查 | 后置；现在只保留来源和修改记录 |
| Marketplace、npm 发布、精细 TUI 渲染 | 后置，先通过本地显式加载使用 |
| 全量异常组合与复杂会话生命周期测试 | 后置；保留与原文丢失、重复修改、权限绕过直接相关的检查 |
| 真实 OMP 加载和一次功能链路验证 | 保留，不能只凭类型检查宣称可运行 |

### 仍然保留的边界

不 fork OMP、不修改 OMP core、不 patch `node_modules`；不绕过宿主命令权限；不把失败说成成功；不以丢失原文换取压缩；不新增自动 compact、自动中断或自动续跑逻辑。

这些边界不是重型流程，不需要额外建设审批平台或通用安全框架。

## 2. 开发方式：少抽象，先复用

优先复用 SoL-Pi 的观察归档、占位、分页恢复、文件队列和相关校验逻辑。OMP 接入代码集中放在少量文件中，不要求先提炼一个兼容多种 Agent 的通用框架。

不要假设“替换包名即可兼容”，也不要先定义一个 `getTool()` 抽象，再把不存在的宿主能力藏在里面。按实际版本核对需要使用的公开接口；确实缺少的能力明确记录。

推荐目录如下，可根据代码体量合并，不必为了目录齐全而创建空文件：

```text
sol-omp/
├── src/
│   ├── index.ts                  # 扩展入口、配置与功能编排
│   ├── config.ts                 # 最小配置读取
│   ├── omp/
│   │   ├── observation-pack.ts  # OMP Context 与恢复工具接入
│   │   └── action-fusion.ts     # 原生编辑委托与后续命令接入
│   └── upstream/sol-pi/         # 选取的上游源码，尽量保留文件名与相对结构
├── tests/                      # 关键算法与错误路径的小测试
├── scripts/smoke.ts             # 实际启动固定版本 OMP 的冒烟入口
├── upstream.lock.json           # 上游 commit、OMP/Bun 版本和源码映射
├── UPSTREAM.md                  # 必要的本地修改及理由
├── package.json
├── README.md
└── LICENSE
```

源码复用时保留版权与许可证。可以为适配修改少量 import、类型或调用边界，但要记录对应上游路径和原因；暂不建设自动补丁生成系统。

`package.json` 中声明 OMP 扩展入口，使用原方案的 `omp.extensions` 方向；在锁定版本中真实验证加载。不要混装完整原版 Pi Runtime 来解决类型或工具执行问题。

## 3. 第一步：固定环境并让 OMP 加载扩展

### 要做的事

1. 记录实际开发环境、Bun 版本、OMP 精确版本和安装形态。
2. 固定一个 SoL-Pi commit，复制本阶段实际需要的文件。
3. 建立最小扩展入口、配置读取和一条可识别的加载日志。
4. 在临时测试项目中，通过显式扩展入口启动 OMP，并正常退出。

上一轮审计提到的 `v18.1.18` 仅可作为 OMP 候选版本，不是本文声明的已支持版本。优先使用开发环境能够实际运行的确定版本；记录它对应的包或二进制，不把不同时间的 `main` 与 Release 混成一个基线。

开发加载命令可从以下形式开始，以所固定 OMP 的 `--help` 和扩展文档为准：

```bash
omp --extension /absolute/path/to/sol-omp/src/index.ts
```

测试脚本应调用选定的 OMP 包或二进制，避免无意使用 PATH 中的另一个版本。初期只测试这一种安装形态，不必同时覆盖源码、全局包和独立二进制。

### 先核对这几个能力，不做大范围 API 审计

| 能力 | 用途 | 缺失时怎么处理 |
|---|---|---|
| 扩展加载、工具注册、Context 事件 | ObservationPack | 这是基本前提，给出明确加载或接口错误 |
| 当前 agent 目录、session 标识和存储路径 | 配置与归档 | 不猜路径；无法安全归档时保持原文，不打包 |
| 原生同名 edit/write 委托 | Action Fusion 编辑部分 | 不重写编辑器，记录不支持的输入或版本 |
| 保留命令权限与拦截的执行路径 | Action Fusion 命令部分 | 暂停该功能，继续交付 ObservationPack |

本阶段只要求真实加载、读取配置、正常退出。不要在这里建设完整兼容性测试平台。

## 4. 最小配置

为减少配置优先级和信任处理，本次 MVP **只读取用户级配置**，暂不读取项目级 `sol-omp.json`。这是对原方案的主动简化，不是遗漏。

配置文件位置由 OMP 当前 profile 对应的公开 agent 目录能力解析：

```text
<当前 OMP agent 目录>/sol-omp.json
```

不要把某个默认 home 路径硬编码为所有用户和 profile 的路径。

内置默认：所有未显式开启的功能均为 `false`。首次开发使用：

```json
{
  "version": 1,
  "observationPack": true,
  "actionFusion": false
}
```

Action Fusion 跑通后，再将 `actionFusion` 改成 `true`。配置修改通过重启 OMP 生效，本次不做热更新。

具体行为：

- `observationPack` 控制是否进行 Context 打包。插件仍加载时可保留只读 `obs_recall`，用于恢复已有引用；README 明确说明这一点。
- `actionFusion: false` 时不注册 edit/write 替换，原生工具行为不变。
- 配置无效时明确报错，不猜测用户意图后继续启用功能。
- 不添加 `onlineContextCompact`、`cacheWriteReadRatio`；Reducer 尚未实现时也不暴露一个可开启但无效的开关。

首次使用由用户按 README 写入配置；安装或加载扩展不得擅自改写用户的 OMP 配置。

## 5. 第二步：ObservationPack 先跑通

### 最小实现

沿用上一轮审计确认的上游行为，而不是重新设计一种通用摘要器：

```text
收到较大的纯文本工具结果
    → 成功保存观察原文
    → 前两次 Context 投影仍保留全文
    → 后续投影替换为稳定占位信息
    → 模型通过 obs_recall 分页读取原文
```

上游基线规则是：大于 `10 KiB` 的合格结果参与；错误结果和非纯文本结果跳过；已生成的 Reducer receipt 不再重复打包。具体细节跟随锁定源码，不额外扩展到用户消息或 assistant 消息。

“原文”指 OMP 实际交给扩展的工具观察文本；它不一定等于源文件全文或工具截断前的完整终端输出。插件不能恢复从未收到的数据。

### 实现注意事项

只修改发给模型的 Context 副本，不原地修改会话消息；保留工具调用标识、工具名、错误状态等协议字段。

先保存原文，再生成占位符。保存失败、目录不可用、内容校验失败时，直接使用原结果，不产生无法恢复的 handle。

归档按当前 session 隔离，复用上游已有的 hash、ID 校验和分页逻辑。不要把第一个 session 的路径缓存成全局路径，也不要让 `obs_recall` 接受任意文件路径。

不建设数据库、后台清理服务或自定义存储平台。默认保留归档；插件禁用或卸载不自动删除已有原文。

### 如何快速验证

在临时测试项目中生成包含中文及“中间标记”的大文本，确保**进入 OMP Context 的实际工具结果**超过阈值，而不只是磁盘文件比较大。必要时用仅用于测试的扩展工具返回固定文本。

让真实 OMP 经历足够多次请求，使占位行为发生，再调用 `obs_recall` 读取中间标记。观察并保留能证明替换和恢复的输出；不能只证明磁盘上多了一个文件。

最少检查：小结果不变；大结果按预期延迟替换；分页内容正确；原始会话内容未被插件覆盖；关闭打包后不再产生新的占位符。

再验证一次同 session 重启后的恢复。分支、跨机器导出、复杂 tree navigation 和全部 Compact 组合后置；本次不拦截或接管 OMP 自身的 Compact。

## 6. 第三步：Action Fusion 接入

### 最小目标

让模型在一次工具调用里完成：

```text
原生 edit/write → 可选 then_run 验证命令 → 同时返回编辑与命令结果
```

先支持本地单文件的编辑或写入，以及有限时的测试、lint、typecheck 命令。不建设跨文件事务，不支持常驻开发服务器的启动管理。

### 原生编辑优先

包装实际存在的 edit/write Schema，保留宿主原有参数语义和编辑模式；移除 `then_run` 后，把原有输入委托给原生同名工具。不要复制重写 OMP 的 hashline、diff 或 LSP 处理逻辑。

上一轮源码审计中的 `ctx.invokeTool()` 是**同名原生工具委托**，不能直接当成“从 edit 调用任意 bash”的能力。开发时仍需针对锁定版本确认。

首版只对能够可靠识别目标文件的输入支持 `then_run`。不支持的原生编辑输入，不带 `then_run` 时保持原生委托；带 `then_run` 时应在修改前明确报不支持，不能先修改文件再声称整个操作没有执行。

不做精细 TUI 渲染；优先使用宿主默认或简单文本显示，明确展示实际执行的命令和结果。

### 后续命令的处理

使用能够经过 OMP 对该命令要求的权限、审批和扩展拦截的公开执行路径。仅仅“调用了宿主 exec 函数”不足以说明这些检查存在。

最关键的检查是：**允许 edit，但禁止 bash 时，融合操作不能执行后续命令。** 同样不能避开已有扩展对命令的阻断。

如果锁定版本没有合适接口：保持 `actionFusion: false`，记录尝试过的接口、相关源码位置和缺少的能力，先交付 ObservationPack。不得用直接启动进程、私有接口或模拟一次批准来绕过。

### 结果与错误必须分开

| 情况 | 返回与副作用 |
|---|---|
| 编辑失败 | 不执行命令，保留真实错误 |
| 编辑成功、命令成功 | 分别报告编辑成功和实际验证结果 |
| 编辑成功、命令非零退出 | 保留编辑；报告验证失败及相关输出，不伪装成测试通过 |
| 编辑成功、命令被拒绝 | 保留编辑；报告命令未执行 |
| 超时或取消 | 传播取消信号；未启动的命令不再启动，已启动的命令按宿主规则终止 |
| 执行前发现外部文件变化 | 复用上游检查，跳过命令并说明原因 |

**编辑已发生后，不得通过“回退到原生 edit”再次执行同一修改。** 本次不做自动回滚和自动重试；调用方能看清“修改完成，但验证未完成”即可。

复用上游现有的文件队列和执行前检查，不新增全局锁。明确其不等于锁住外部编辑器，也不保证测试期间整个工作区完全不变。

## 7. 只保留这一组最小验证

不建设大矩阵；用少量自动化断言加一个真实 OMP 会话覆盖以下内容。

| 场景 | 最少证明什么 |
|---|---|
| 扩展加载、开关与正常退出 | 确实加载所写扩展；功能关闭时不继续替换对应行为 |
| ObservationPack 打包与恢复 | 前期全文、后期占位、原文不被覆盖、分页恢复正确 |
| 归档失败与 session 重启 | 保存失败保留全文；同 session 可恢复，不能串到别的 session |
| 编辑加一次成功验证 | 文件确实被原生工具修改，验证命令确实执行并返回 |
| 编辑失败、命令失败 | 编辑失败不启动命令；命令失败不重复编辑、不假报成功 |
| 命令被拒绝或取消 | 没有执行未授权命令，没有因重试产生第二次修改 |

关键功能断言必须失败时返回非零退出码，不能用“打印预期字样”替代检查。

项目只需要实现以下本地入口约定：

```bash
bun run typecheck
bun test
bun run smoke
```

这些是开发者需要创建的脚本接口，不代表本文已执行。`smoke` 要实际启动固定版本 OMP，不能仅导入一个函数后打印 PASS。

已有可用模型配置时，补一次真实模型调用扩展工具的链路。没有模型凭证时，继续完成本地测试、真实加载和可执行的复现步骤，交付中标记 `MODEL_E2E=BLOCKED（缺少凭证）`，不得宣称模型侧链路已验证。不要为弥补凭证缺失而建设复杂代理或改动用户认证配置。

基本 CI 可在本地跑通后加入：先跑固定环境的类型检查和关键测试；涉及账号的真实模型验证由开发环境执行，不要求塞入 CI。

## 8. 交付方式与完成标准

先交付 GitHub 仓库或本地源码目录，通过显式入口加载。Marketplace、npm 发布不是本次完成条件。

README 至少写清楚：实际验证的 OMP/Bun/系统版本、依赖安装与加载方法、配置示例、如何开关、如何运行测试、原文归档位置与保留行为，以及已知限制。

**最小可运行预览版：** OMP 可加载；ObservationPack 可打包和恢复；Action Fusion 若未接通则明确关闭并列出阻塞。该预览版不能宣称完整功能已完成。

**本次完整目标：** 在预览版基础上，Action Fusion 的成功、失败和权限拒绝路径跑通。支持范围只写实际测试的版本和环境，不写未经验证的 `>=18.x`。

交付报告保持简短，给出：代码位置或 commit、真实执行的命令及结果、尚未完成的项目。使用 `PASS / FAIL / BLOCKED / NOT_RUN` 区分状态；不附维护难度评分，不宣称未经测量的 token 或成本收益。

## 9. 后续阶段：Evidence-Preserving Reducer

本次不以 Reducer 阻塞前两个功能交付。实现时沿用上游定义：它是**辅助模型处理较长诊断日志，并校验结构化证据摘要**，不是通用的用户需求或会话去重器。

推荐的后续接入方式：

```text
工具原始结果 → 保留原结果与归档
                  ↓
           限时调用辅助模型
                  ↓
           校验并缓存 receipt
                  ↓
Context 投影时使用已验证 receipt；不可用则仍用原结果
```

为了保持原始会话内容，工具结果处理阶段不直接用 receipt 替换正常返回值。这是相对于上游 `tool_result` 替换路径的接入差异，应记入 `UPSTREAM.md`。

每条日志按 session、工具调用和内容 hash 去重处理，不在每次 Context 请求时重复调用辅助模型；不创建脱离会话取消控制的后台任务。重启后没有有效 receipt 时直接使用原文，无需先建设持久化摘要数据库。

默认关闭，用户显式配置宿主已有的 provider/model 后才启用；不把密钥写入插件配置。说明日志可能外发且有额外调用费用，不承诺“绝不上传代码”，因为日志中可能包含代码片段。

保留来源 hash、逐字引用、状态和大小校验；模型不可用、超时、疑似敏感内容或校验失败时保留原结果。强调“引用真实”不等于“摘要完整”，receipt 不能单独证明测试全部通过。无需为此建立性能对照实验。

## 10. 后续维护：现在留记录，之后补自动化

现在只做两件事：在 `upstream.lock.json` 记录上游 commit、复制文件映射、实际验证的 OMP/Bun 版本；在 `UPSTREAM.md` 记录本地改动。不要省略来源记录，否则后续难以同步。

功能跑通后再补：

```text
SoL-Pi 新 commit
    → 下载选定文件到候选目录
    → 展示与当前版本的差异
    → 应用已记录的适配
    → 跑关键测试
    → 创建更新 PR
```

不能直接覆盖包含本地改动的运行源码，也不直接推送主分支。常规更新尽量脚本化；遇到上游语义变化或冲突时保留人工审查，不承诺完全免维护。

OMP 升级先尝试新 Release 的加载与最小测试，通过后再更新已验证版本。多版本定时 CI、Windows 原生环境和完整分发流程均可随后添加，不影响首版交付。

## 11. 给执行 AI 的工作指令

按本文顺序直接实施，不先写一套更大的设计方案。

1. 优先做出可以真实加载的扩展；随后完成 ObservationPack，再接 Action Fusion。
2. 复用上游现有逻辑，用最少文件完成 OMP 适配；不要为了“架构完整”创建通用引擎或空模块。
3. 只围绕当前功能核对所需接口。一个功能被宿主能力阻塞时，记录证据并继续其它可交付工作；不以等待确认代替推进。
4. 不为了赶进度绕过权限、重复执行修改或丢弃原文；其它非必要测试和自动化可以后置。
5. 完成后提交代码、README、来源记录和简短运行结果；未运行的项目明确标注，不推测 PASS。

最终优先级：
